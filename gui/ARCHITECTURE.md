# معماری GUI — قرارداد ثابت پروژه (از فاز ۲ به بعد)

این سند مرجع هر تغییر آینده در پوسته‌ی گرافیکی است. موتور (core/) و UI (gui/)
کاملاً جدایند؛ هیچ‌وقت منطق شبکه‌ای داخل gui/ ننویس و هیچ‌وقت Qt داخل core/.

## نقشه‌ی فایل‌ها

| فایل | نقش |
|---|---|
| `core/session.py` | موتور سشن — فقط اینجا رفتار شبکه تغییر می‌کند |
| `gui/app.py` | پنجره، تب‌ها، ویجت‌های سفارشی (StatusDot/Sparkline/BarList)، چرخه‌ی سشن |
| `gui/model.py` | مدل جدول پکت‌ها (QAbstractTableModel) و رندر رکوردها |
| `gui/theme.py` | تمام رنگ‌ها (`COLORS`)، استایل‌شیت و فونت‌ها — تنها منبع رنگ |

## الگوهای اجباری (از این به بعد هر قابلیت جدید همین‌طور)

1. **دیتا از موتور به UI فقط دو راه دارد:**
   - رویداد کم‌نرخ (لاگ، وضعیت، پایان) → `Bridge` سیگنال‌های pyqtSignal
   - دیتای پُرنرخ (پکت، summary) → QTimer polling از روی tap ها (take_new / summary)
2. **هر قابلیت داده‌ی جدید، اول یک tap می‌شود** (`taps/<name>.py` با `kind`،
   `start/stop/summary`، فقط کپی می‌خواند، هرگز در مسیر فوروارد نیست) —
   بعد UI از `session.taps.get(name)` می‌خواند. CLI و GUI هر دو از آن استفاده می‌کنند.
3. **ویجت‌های سفارشی با QPainter** مثل StatusDot/Sparkline/BarList — بدون
   وابستگی جدید (QtCharts ممنوع؛ python3-pyqt6 آن را ندارد).
4. **رنگ فقط از `theme.COLORS`** — رنگ هاردکد داخل ویجت ممنوع.
5. **مقاومت:** هر کال‌بک تایمری با `_safe_timer` بسته شود؛ انیمیشن‌ها شیء دائمی
   parented هستند (نه ساخت/حذف مکرر — باگ deleted-object دوبار گاز گرفت).
6. **تضمین خروج:** بستن پنجره باید `session.stop()` و join ترد موتور را
   تضمین کند — تارگت هرگز با ARP سمی رها نمی‌شود.
7. **دیتا بعد از stop منجمد می‌ماند** — Summary باید بعد از پایان سشن هم
   خوانا باشد (tap ها را خالی نکن؛ فقط sniffer ها را ببند).

## دستور پخت یک قابلیت جدید (چک‌لیست)

1. داده از کجای موتور می‌آید؟ اگر ترافیک است → tap جدید؛ اگر وضعیت است →
   `_status_snapshot` در session.py
2. در `TapManager` ثبتش کن (نام + کلاس)
3. در UI: polling timer یا سیگنال + ویجت نمایش (QPainter اگر خروجی خاص است)
4. رنگ‌ها را به `COLORS` اضافه کن، نه داخل کد ویجت
5. `_safe_timer` بگذار، closeEvent را نشکن، و با QT_QPA_PLATFORM=offscreen
   smoke test بگیر قبل از تحویل

## CLI همیشه همسطح GUI است

هر داده‌ای که GUI می‌بیند باید در CLI (taps/summary) هم موجود باشد —
هر دو پوسته‌ی همان موتورند (الگوی nmap/Zenmap).
